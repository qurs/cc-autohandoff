# cc-autohandoff
Экономия токенов с помощью автоматического переноса сессии (handoff) в Claude Code

При достижении **150 000 токенов текущего контекста** плагин останавливает работу на ближайшей
границе hooks, и субагент на младшей модели **Claude Haiku 5.5** готовит сжатую сводку
и инструкцию для продолжения работы в свежей сессии. В desktop-приложении Claude плагин затем
создаёт одну новую сессию в том же проекте с этой инструкцией. В CLI и IDE новая сессия
открывается вручную по ссылке на `START-NEXT-SESSION.txt`.

Writer работает внутри текущей сессии как субагент плагина `cc-autohandoff:handoff-writer`.
Отдельный Claude CLI, его установка и авторизация не нужны: достаточно Claude Desktop
или Claude Code, в котором вы уже работаете.

Сводка и инструкция для нового чата пишутся на английском. Новый чат получает только
`HANDOFF.md` как источник прежнего контекста и явный запрет читать старую историю.
Рабочие файлы проекта доступны для продолжения задачи. Начальный контекст также включает
системные инструкции и определения инструментов, поэтому даже короткий handoff
не означает старт с нуля токенов.

## Установка

Добавь в `.gitignore` проекта:
```
.cc-autohandoff/
```

Выполни в терминале:

```powershell
claude plugin marketplace add qurs/cc-autohandoff
claude plugin install cc-autohandoff@cc-autohandoff
```

Внутри Claude Code те же команды доступны как `/plugin marketplace add qurs/cc-autohandoff`
и `/plugin install cc-autohandoff@cc-autohandoff`. В Claude Desktop плагин можно добавить
через управление плагинами приложения, указав тот же marketplace.

## Как это выглядит

1. Контекст достиг порога (или хост попытался выполнить compact).
2. Hook блокирует новые действия и просит основную модель вызвать writer-субагента
   с точными аргументами. Частично выгруженная переписка лежит во временных файлах
   `.cc-autohandoff/<ключ>/source/`, которые удаляются после ответа writer.
3. Writer отвечает JSON-объектом; плагин проверяет его и пишет `HANDOFF.md`
   и `START-NEXT-SESSION.txt`.
4. В Claude Desktop создаётся новая сессия с текстом `START-NEXT-SESSION.txt`;
   иначе вы получаете ссылки на оба файла и открываете чат сами.

## Если handoff не удался

Compact и новая работа остаются заблокированы, а уведомление показывает ошибку.
Отправь в этот же чат сообщение `CC_AUTOHANDOFF_RETRY`: источник подготовится заново,
и модель снова вызовет writer. Тот же повтор доступен командой `retry` из уведомления.
Диагностика без текста переписки сохраняется в `writer-errors.log`.

## Настройки

`handoff-settings.json`:

| Ключ | Значение |
| --- | --- |
| `threshold_tokens` | порог текущего контекста, по умолчанию 150000 |
| `model` | фиксированная модель writer, только `claude-haiku-5-5` |
| `continuation` | `claude-desktop` или `manual` |
| `writer_timeout_seconds` | сколько ждать ответа writer, прежде чем считать попытку неудачной |
| `max_source_chars`, `part_chars`, `tool_output_chars` | бюджет выгрузки переписки для writer |

Вне desktop-приложения Claude режим `claude-desktop` автоматически работает как `manual`.
Если ответ приложения о создании сессии потерян, автоматического повтора нет: проверь список
сессий и только затем выполни `retry-continuation ... --confirm-no-chat` из уведомления.
