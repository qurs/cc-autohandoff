## Живой writer Codex

20 октября 2026 года штатная функция `generate` запустила отдельный
`gpt-6-luna` через Codex CLI **0.163.0-alpha.10.2** на трёх синтетических сообщениях.
Настоящий transcript не передавался. Команда использовала фиксированную модель,
`--ephemeral`, `--ignore-user-config`, read-only sandbox, отключённые hooks,
plugins, apps, memories, shell, unified exec и веб-поиск.
Назначение этих CLI-флагов сверено с
[официальной справкой Codex](https://learn.chatgpt.com/docs/developer-commands?surface=cli).

Первый запуск в ограниченной среде завершился до ответа модели с ошибкой
`failed to initialize in-process app-server client: Отказано в доступе (os error 5)`.
После разрешённого запуска CLI вне внешнего ограничения writer завершился успешно:
состояние `ready`, корректный JSON по схеме, созданы `HANDOFF.md` и
`START-NEXT-SESSION.txt`. В журнале только сообщение модели и завершение хода,
вызовов инструментов не обнаружено.

Luna сохранила требования исходной переписки и следующий шаг, не выдала запланированный
тест за выполненный и отметила отсутствие независимой проверки файлов.
Источник, результат и диагностика обеих попыток сохранены локально в игнорируемом `.build/`.

Это живая проверка writer из исходников. Значение контекста 120000 задано в синтетическом
состоянии; естественное накопление такого контекста, hooks опубликованного executable
с живой моделью, доверие hooks в desktop UI и полный цикл создания и открытия нового
чата этой проверкой не подтверждены.

## Попытка живого writer Claude Code

Тот же короткий сценарий запущен штатной функцией `generate` с фиксированной моделью
`claude-haiku-5-5` и CLI **2.1.304** из `.build/claude-cli`.
Использован отдельный профиль `.build/claude-remote-test`; `auth status` подтвердил
авторизацию. Команда использовала print mode, JSON schema, `--tools ""`, пустой MCP
с `--strict-mcp-config`, отключённые hooks и сохранение сессии, без fallback модели.
Параметры сверены с [официальной справкой Claude Code](https://code.claude.com/docs/en/cli-reference).

Первый процесс завершился с `ECONNREFUSED`. Повторная диагностическая попытка вне
внешнего ограничения среды завершилась с
`API Error: Unable to connect to API: SSL certificate hostname mismatch`.
Оба процесса вернули код 1; состояние handoff — `failed`, `modelUsage` пустой,
входные и выходные токены — 0. Ответ Haiku не получен, артефакты готового handoff
не созданы. Эти результаты не подтверждают доступность или работу модели.
Диагностика сохранена в игнорируемом `.build/`; другая модель не использовалась,
проверка TLS не отключалась, настройки пользовательских плагинов не менялись.

Следующая живая проверка Haiku требует устранить ошибку сертификата соединения с API.
Полный цикл hooks с живыми моделями и доставка нового чата через Codex desktop
остаются непроверенными. Повторная команда
`python -m unittest discover -s tests -v` прошла: 41 тест, `OK`.
